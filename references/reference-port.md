# Reference port

Use before adapting code, design, or a workflow from another project.

1. Read both the reference and the destination. Check the reference's license and current behavior from the original source.
2. Map invariants, inputs, outputs, side effects, and failure cases before proposing code.
3. Show three compact views: reference versus proposed behavior; preserved, changed, and removed behavior; edge cases and whether the adaptation covers them.
4. Add 2–3 knowledge questions only when the reviewer must understand a subtle semantic difference. A completed quiz confirms understanding; it does not authorize copying, publishing, or merging.
5. The reply names the adaptation and the exact behavior to preserve.

Do not paste large portions of licensed source into the artifact. Link the original instead.
