# Grounded brainstorm

Use for an open product or operational problem when the possible interventions depend on what current evidence says. For a chain of architectural decisions, use `interview`.

1. Gather the smallest relevant set of primary evidence: product events, customer interviews, incident records, or code paths. Give every metric a source, time range, and definition.
2. If evidence is unavailable, show the measurement gap first. Do not invent a conversion rate or recommend a change as if the data existed.
3. Propose 4–8 distinct interventions. Each card names the observed problem, a concrete change, the evidence behind it, and a rough effort size.
4. Sort by effort or expected learning value. Let the user mark what resonates; those marks are signals, not final approval.
5. Build a reply listing selected interventions and one first experiment or measurement step.

Put implementation detail in collapsed sections so the initial view stays readable.
